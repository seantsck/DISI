## Order

1. Back up (`pg_dump` through the safe runner, mode 600, SHA-256 file; restore-verified on PostgreSQL 17: the verifier with
   `EXPECTATIONS_THROUGH_054A` 258/258 on the restored copy; 055 applies, reruns, rolls back and reapplies on it).
2. Read-only, on production, before the apply: the HEAD verifier fails exactly the five moved pins (players_total 322, league_benchmark_players
   102, player_evaluations 105, scouting_legacy_ranks_total 113, scouting_legacy_ranks_backfilled 102); `EXPECTATIONS_THROUGH_054A` is 258/258;
   Cartaya's Dodgers signing stores rank 1 and Rosario's NULL; the stored evaluation fingerprint is `af9ec05f...`.
3. Apply `055_international_benchmark_2017_2018.sql` through the safe runner (SHA-checked, `ON_ERROR_STOP`). One transaction, applied once.
   About 4 s on PGlite and PostgreSQL 17, plus one snapshot refresh.
4. Verify read-only: live verifier 258/258; catalog 79 / 156 / 37; generation 11 on all eleven snapshots, drift 0; the counts above; the
   Dodgers rows byte-identical (Rosario NULL); benchmark reach 140 / 30 / 110; evaluation current at `67f2f80c...`, no model supported;
   probabilities, expected values and recommendations 0.
5. Merge the PR (normal merge commit); the GitHub -> Vercel production deploy follows (no application change).
6. Smoke: `/league` (the 2017 and 2018 Top 30 samples listed, 28 and 22 tracked), `/prediction-readiness` (the benchmark reference baseline from
   140 labelled rows; Dodgers targets not supported; no probability), `/players/diego-cartaya` and `/players/jerming-rosario` (unchanged),
   `/players/wander-franco` (a benchmark dossier), `/`, `/research`, `/methodology`; HTTP 200, no "Data unavailable"; the current deployment's
   logs clean.
7. Freeze on a bookkeeping-only branch (058 -> 059 frozen, `UNRELEASED_ADDITIONS = []`).

Do not re-apply 055 in production to test idempotency (proven on PGlite and PostgreSQL 17). If step 3 fails nothing is committed.

## Rollback

`rollback-055.sql` (one transaction, guarded: it refuses unless 055 is applied and refuses if later research depends on a 055 player) removes
exactly the 055 rankings (the 026 guards disabled inside the transaction only, as rollback-050), players, signings, members, coverage rows,
populations, audits, outcomes and evidence, restores the 050 evaluation rows exactly, proves the Dodgers signings unchanged and the guards
re-enabled, and refreshes once (generation +1). The sources stay as provenance. **055 can be applied again after its rollback.**
